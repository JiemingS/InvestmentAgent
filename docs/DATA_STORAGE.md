## Milestone 5 conversation storage

The default conversation database is `D:\AI\InvestmentAgent\.data\agent.sqlite3`. It is a sibling of the configured portfolio file unless `INVESTMENT_AGENT_DB_PATH` selects another location. The backend rejects configurations that point conversation storage at the portfolio or research database.

Schema v2 adds `quick_prompts`, with UUID, title, full prompt text, display order, and creation/update timestamps. Prompts are shared across conversations, persist across restarts, and are deleted only through their own management action. The migration adds a table and index. It leaves existing conversation, portfolio, and research records untouched.

- Schema v1 creates `conversations` and `conversation_turns`. A turn pairs one user message with its assistant response, timestamps, generation state, and original tool activity. The response snapshot includes citation metadata, source text and the exact bounded evidence input passed to synthesis. Validated tool arguments are limited to known noncredential fields. Errors and elapsed milliseconds are saved when available. Failed attempts replaced by a retry are archived in the turn.
- Conversation records survive app and Ollama restarts. Refreshing news, charts or calendars does not rewrite snapshots. No automatic history purge. Deleting a conversation cascades to its turns and archived attempts in the conversation file. Portfolio entries, market cache and shared research remain in their separate files.
- The API creates and lists conversations at `/api/agent/conversations`. Fetch, rename and delete use `/api/agent/conversations/{id}`. Send a message to `/api/agent/conversations/{id}/messages` with a client-generated UUID and question. Appending `?stream=true` streams activity and the final result. Repeating a completed UUID with the same question replays the saved result. An interrupted or failed newest turn can retry under its original UUID.
- A database lease and transaction guard prevent overlapping generation within one conversation. Disconnecting a streamed request marks it interrupted. A crash can leave a pending turn until its three-minute lease expires; opening the chat or attempting another write reconciles it. Interrupted turns retain any recorded activity, but may lack a final answer and citation snapshot.
- Gemma gets at most three completed prior turns, newest first for selection, from the active conversation. The combined allowance is 4,800 characters with each assistant excerpt capped at 900 characters. Retained turns are then sent chronologically. Only direct assistant prose and deterministic local holdings, market and clock facts are reused. Historical webpage excerpts and topic interpretations stay outside the tool-enabled context. External providers receive their existing bounded query or page URL, independent of the transcript.
- The browser stores the selected conversation UUID and active Agent view in browser storage for reload. Message content is stored in SQLite. To back up the conversation file consistently, stop the backend and copy it along with any other desired databases to a private backup location.
