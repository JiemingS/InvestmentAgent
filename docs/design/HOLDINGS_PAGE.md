# Holdings 页面功能与实现

**Holdings & Market Data** 是手动录入投资交易、查看当前持仓和回顾历史行情的页面。金额以美元显示，持仓成本采用加权平均法。

## 页面功能

| 区块 | 显示内容与操作 |
| --- | --- |
| 页头 | 显示页面名称、计价货币和成本口径。**Refresh** 重新读取交易与估值。 |
| Investment account filter | 默认是 **All accounts**，可切换到单个已登记账户。有未填写账户的旧记录时，额外提供 **Unassigned transactions**。筛选联动顶部汇总、持仓、市值历史、配置图和交易历史。Daily prices 的股票选项和买卖标记也随筛选结果更新。切换账户会保留图表时间范围。 |
| Portfolio summary | 五张卡片显示当前市值、未实现盈亏、净投入资金、剩余成本和已实现盈亏。报价提示显示 Yahoo Finance、最早报价时间，以及过期缓存或盘中日线状态。 |
| Add / Edit transaction | 输入股票代码、买卖方向、投资账户、交易日期、股数、每股价格和手续费。新交易默认买入、当天、零手续费，并预填当前持股数最多的股票代码（如果有）。编辑时带入原值，旧记录可补填账户。 |
| Open positions | 按股票代码显示仍有持仓的股票，包括股数、平均每股成本、成本基础、最新价格、市值和未实现盈亏。 |
| Portfolio market value | 历史市值折线图。**Range** 可选 1 个月、3 个月或 1 年，默认 3 个月。悬停可查看当日美元市值。 |
| Allocation by market value | 按股票展示当前市值占比的环形图。标签显示股票代码和比例，悬停可查看市值。 |
| Daily prices | 单只股票的日 K 线与买卖标记。可切换股票、查看行情来源和更新时间，并用 **Refresh prices** 强制刷新。 |
| Transaction history | 按日期倒序显示日期、代码、账户、买卖方向、股数、每股价格和手续费。同一天的交易按编号倒序。每笔可 **Edit** 或 **Delete**，删除前会要求确认。 |

## 实现方式

### 账户、录入与台账

- React 在 [页面组件](../../frontend/src/main.tsx) 中管理账户筛选、录入状态和图表范围。股票代码和账户共用 [可搜索下拉组件](../../frontend/src/SavedValueField.tsx)。历史账户按名称去重，匹配时忽略大小写。选定账户后，交易历史在前端筛选，持仓与市值图表使用同一账户范围的后端估值。
- 新交易默认选择有当前持仓且总市值最高的已登记账户。未登记账户的交易不参与排名。有候选账户缺少市值时，候选账户统一按剩余成本比较。没有符合条件的持仓账户时，回退到最常使用的历史账户，次数相同优先最近交易的账户。无历史账户时预填可编辑的 `Main Account`。编辑旧交易时，原账户为空则继续显示为空。
- [交易 API](../../backend/app/main.py) 使用 `GET /api/transactions` 读取台账，使用 POST、PUT 和 DELETE 保存变更。[SQLite 迁移](../../backend/app/db.py) 为旧交易新增可空的账户列。[交易写入逻辑](../../backend/app/transactions.py) 在同一写入事务内校验台账，发现历史卖出超过可用股数时回滚。后端还会校验股票代码、日期、股数、价格和手续费。 [输入校验](../../backend/app/schemas.py)

### 估值与图表

- `GET /api/portfolio/valuation` 返回持仓与顶部指标，`GET /api/portfolio/history` 返回日期范围内的历史市值。省略 `account` 时使用完整台账，传入账户名时使用对应账户的交易，传入空值时使用未登记账户的交易。**All accounts** 按股票代码汇总，单账户按该账户的买卖记录单独计算。[接口定义](../../backend/app/main.py)
- [持仓计算](../../backend/app/portfolio.py) 按交易日期和编号重放台账，以加权平均成本计算已实现和未实现盈亏，并在对应日期处理拆股。[估值服务](../../backend/app/valuation.py) 将持仓与行情结合。历史估值逐日使用当天持仓和已定稿的日线。如果持有的股票缺少当日报价，该日市值为空，折线保留缺口。
- [图表组件](../../frontend/src/MarketPanels.tsx) 用 ECharts 绘制历史市值和当前配置，用 [Lightweight Charts](../../frontend/src/Candles.tsx) 绘制日 K 线。图表和持仓表复用当前账户范围的估值。日线图用箭头和文字同时标识买卖，交易日期缺少对应 K 线时会说明。全部持仓都有报价时才显示完整配置比例。

### 行情缓存与刷新

- [Yahoo 行情适配器](../../backend/app/yahoo.py) 通过 `yfinance` 取得开盘价、最高价、最低价、收盘价、成交量、拆股和分红数据。[行情服务](../../backend/app/market.py) 以股票代码和交易日为键写入 SQLite。
- 页面加载以及股票或时间范围切换会请求行情。后端按需补拉缺失交易日，盘中日线缓存满 15 分钟后可在下一次请求时刷新。收盘 1 小时后，下次请求会尝试更新为最终日线。补齐最近一段数据时，服务可能重抓前两个交易日以覆盖修订。页面没有定时轮询。 [日线定稿规则](../../backend/app/exchange.py)
- **Refresh prices** 对当前股票走强制刷新接口，从所选范围起始日重新抓取至当前交易日。行情源失败时，页面可继续展示已有缓存并提示过期或缺失。 [刷新接口](../../backend/app/main.py)

## 用户友好的设计

- **常用值预填。** 新增表单直接给出常用股票和主账户。股票代码自动转换为大写。代码和账户都允许输入新值，并可用历史选项减少重复录入。
- **可用键盘完成选择。** 可搜索的下拉栏支持方向键、Enter 和 Esc。展开时淡入约 120 毫秒，关闭时立即收起。系统开启减少动态效果时会跳过动画。
- **提示显示在屏幕底部正中。** 成功提示停留约 4 秒，后台保存失败时显示具体原因，停留约 7 秒。失败后保留表单输入，便于修改重试。浮窗不占页面布局空间。
- **状态可辨认。** 持仓和图表区分加载中、无记录、无持仓和数据不可用等情况。过期报价、盘中临时日线和缺失行情均有文字提示。
- **适配主题和窄屏。** 页面和图表共用深蓝、浅色主题的语义颜色。窄屏下交易表单、持仓和图表转为纵向排列，宽表可独立横向滚动。 [页面样式](../../frontend/src/style.css) · [主题规范](UI_DESIGN_SYSTEM.md)
